# 音声コミュニケーションアプリ(Webアプリ版)

スマートフォンのブラウザ(横画面)で動作する、6ボタンの音声コミュニケーション支援アプリです。
インストール不要。GitHub Pagesでそのまま公開できます。

## 公開方法(GitHub Pages)

1. このリポジトリを GitHub にプッシュする。
2. GitHub の Settings → Pages を開く。
3. "Build and deployment" の Source を **Deploy from a branch** にし、
   Branch を `main` / `/(root)` に設定して Save。
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される。

## 音声・画像ファイルの配置

- `assets/audio/` に `ohayo.mp3`(おはよう)、`otsukare.mp3`(おつかれ)、
  `koremite.mp3`(これ見て)、`FeedbackSound.mp3`(操作音「ピコッ」)を配置してください。
- `assets/icons/` に 6 枚のアイコン画像(`sun.webp` `hand.webp` `finger.webp`
  `1.webp` `2.webp` `3.webp`)を配置してください。背景を透過したWebP形式にしています。

## 使用している外部ライブラリについて(実装方針の補足)

低い声・高い声の実装では、ご提示いただいた `soundtouchjs` の利用を検討しましたが、
以下の理由により **外部ライブラリに依存しない自前実装(グラニュラー方式のピッチシフト)** を
第一候補として採用しました。

- ビルド不要・CDN読み込み不要のため、iOS Safari / Android Chrome 双方での
  読み込み失敗リスク(CDN到達不可、ESM未対応バージョン差異など)を避けられる。
- オフライン処理(録音終了後にまとめて加工する方式、仕様書 第18章)に必要な
  API のみで完結し、依存ライブラリのバージョン変更による破壊的変更の影響を受けない。

具体的には、録音した音声を短いグレイン(窓)に分割し、各グレインを目的のピッチ比で
リサンプリングしてから元の時間位置に重ね合わせる(オーバーラップ・アド)方式で、
発話時間をほぼ維持したままピッチのみを変化させています。

もし将来的により高品質なピッチシフトが必要になった場合は、`js/app.js` 内の
`pitchShiftBuffer` 関数を `soundtouchjs`(`https://cdn.jsdelivr.net/npm/soundtouchjs/+esm`
を `import()` する形)に差し替えることで対応可能です。差し替える場合は事前に
実機(iOS Safari / Android Chrome)での動作確認をお願いします。

ロボット声は Web Audio API(`OfflineAudioContext`)のみで実装しています。
リングモジュレーション・ビットクラッシャー(WaveShaperによる量子化)・トレモロ・
軽度のディストーション・ハイパス/ローパスフィルターを直列に組み合わせています。

## 実機テストについて

Claude側では実機(iPhone Safari / Android Chrome)での動作確認ができないため、
以下を必ずご自身の端末で確認してください。

- [ ] 上3ボタンで正しい音声が再生される
- [ ] 下3ボタンの長押し(0.5秒以上)でマイク許可ダイアログが表示され、録音できる
- [ ] 録音済みボタンの短押しで加工後の音声が再生される
- [ ] 低い声・高い声で発話時間が大きく変わらない
- [ ] ロボット声で発話内容が聞き取れる程度に加工されている
- [ ] 10秒で自動的に録音が終了する
- [ ] 0.3秒未満の録音が保存されない(既存の録音が残る)
- [ ] 録音中に指がボタン外に動いても録音が続く
- [ ] 再生中・録音中に他のボタンが反応しない
- [ ] 画面のスクロールや長押しメニュー、拡大操作が発生しない
- [ ] 横画面で6ボタンが大きく表示される

もし iOS Safari で音声再生が無音になる場合は、`AudioContext` の `resume()` が
ユーザー操作(タップ)を起点に呼ばれているか(`js/app.js` の `unlockAudioOnce`)を
ご確認ください。

## 仕様にない機能について

チュートリアル・PWA化などは実装していません。
